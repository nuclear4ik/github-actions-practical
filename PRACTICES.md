## Практика 6

`monitoring/` содержит Compose, Prometheus, правила, provisioning Grafana
и скрипты. Используются реальные метрики экспортера: `pg_up` и
`pg_stat_database_numbackends`. Grafana доставляет уведомления через
Slack-совместимый входящий вебхук Mattermost; публичный URL вебхука —
`/hooks/<token>`, а не API для управления вебхуками.

`.github/workflows/monitoring.yml` рассчитан на ветку `monitoring`:
валидация → роль exporter → проверка файлов дашбордов → деплой → reload → проверка.
Для мониторинга нужны существующие сети приложения и Mattermost.
`APP_NETWORK` по умолчанию `docker-fullstack_app_net`; имя БД и пользователь
берутся из секретов практики 3. Экспортер подключается к `app-db`.

Дополнительные секреты: `PG_EXPORTER_PASSWORD`, `GRAFANA_PASSWORD`,
`MATTERMOST_WEBHOOK_URL`. Сбор конфигурации через `docker compose config`
следует выполнять с `-q`, чтобы значения секретов не печатались.

Следующие проверки после развёртывания: четыре цели UP, `pg_up = 1`, живые
данные в дашбордах 1860, 19908 и 9628, тестовый алерт, остановка app-db,
уведомление Firing, восстановление app-db, уведомление Resolved,
два успешных прогона workflow. На macOS node_exporter и cAdvisor видят
Linux-виртуальную машину Docker; для метрик Linux-хоста нужен Linux-стенд.
